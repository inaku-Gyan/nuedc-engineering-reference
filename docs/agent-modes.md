# Agent Modes

本文定义使用和维护本知识库时的 Agent 权限模式。模式是行为规范，用于让可信
Agent 的动作可预测；它不是文件系统、网络或 Git 的安全边界。

## 配置文件

根目录 `.agent-mode.yaml` 是本地配置，不提交 Git。格式固定为：

```yaml
schema_version: 1
mode: readonly

git:
  auto_commit: false
  auto_push: false
```

允许的字段和值：

| 字段 | 类型 | 允许值 |
| --- | --- | --- |
| `schema_version` | 整数 | 当前仅 `1` |
| `mode` | 字符串 | `readonly`、`curate-on-use`、`autonomous`、`maintainer` |
| `git.auto_commit` | 布尔值 | `true` 或 `false` |
| `git.auto_push` | 布尔值 | `true` 或 `false` |

不接受其他顶层字段或 `git` 子字段。`auto_push: true` 要求
`auto_commit: true`；`readonly` 要求两项均为 `false`。

配置文件对每个本地 checkout 独立生效。通过 Git Submodule 引入时，也要在
Submodule 工作树内单独初始化。

## 强制初始化向导

`.agent-mode.yaml` 不存在时，Agent 不得执行原任务，也不得自行采用默认模式。
Agent 要记住原任务，然后依次完成：

1. 询问模式。
2. 写入模式允许修改仓库时，询问是否自动提交。
3. 仅当自动提交开启时，询问是否自动推送。
4. 展示完整 YAML。
5. 说明 `auto_commit` 会创建本地提交，`auto_push` 会修改当前分支的远端状态。
6. 获得明确确认后写入文件。
7. 重新读取并校验，通过后恢复原任务。

用户取消或无法回答时，不创建配置，也不继续原任务。

## 配置修复

配置存在但无效时，在用户确认前不得覆盖。Agent 应：

1. 列出无法解析或违反规则的具体字段。
2. 保留可确认有效的字段。
3. 只询问缺失或无效的配置项。
4. 展示规范化后的完整配置及与旧配置的差异。
5. 用户确认后覆盖并重新校验。

未知字段也视为错误，以免拼写错误静默改变权限。Agent 不得借修复过程扩大用户
没有确认的权限。

## `readonly`

### 允许

- 读取本地目录、摘要、元数据、摘录和原件。
- 联网搜索、核验最新官方信息，并在回答中引用。
- 运行不会持久修改仓库的检查。
- 在 `.agent-cache/`、`.tmp/` 等已忽略目录生成临时 PDF 页面、OCR 或预览；
  任务结束后清理。
- 报告缺失、过期、冲突或值得整理的内容。

### 禁止

- 创建、修改、移动或删除持久资料。
- 把在线资料下载到 `library/`、`inbox/` 或其他持久目录。
- 创建提交、推送分支或修改远端状态。

初始化或经用户确认的配置修复，是唯一的持久写入例外。

## `curate-on-use`

包含 `readonly` 的能力。

当本次任务实际读取了尚未文本化的原件内容，并满足至少一项条件时，应进行整理：

- 内容可能被后续任务重复查询；
- 原 PDF 难以搜索、没有文本层或表格结构混乱；
- 包含重要限制、边界条件、版本差异或易误用参数；
- 需要组合多页内容才能清楚回答本次问题；
- 内容已实际用于本次回答，整理后能明显减少下次上下文。

允许新增或更新直接相关的：

- 资料包 `README.md`；
- `meta.yaml` 的提取覆盖信息、来源核验信息；
- `extracts/` 中按单一主题组织的摘录；
- `knowledge/` 中可复用的跨资料结论；
- 相应 `catalog/` 导航入口。

不应为单个简单事实、已有摘要充分覆盖的内容或未经核验的推测创建摘录。不得下载
或归档新原件，不得创建与仓库现有原件无关的新资料包。可以联网核验版本和官方
入口，并把核验结果写入直接相关的元数据或摘要。

## `autonomous`

包含 `curate-on-use` 的能力。

满足以下任一条件时，应围绕当前任务主动联网检索：

- 目标器件、工具、标准或赛题资料尚未入库；
- 本地摘要、摘录和原件仍不足以可靠回答；
- 版本很可能已经过期；
- 关键设计需要勘误表、参考手册或其他控制文档才能核验。

检索和入库规则：

1. 优先厂商、标准组织、NUEDC 和项目官方来源。
2. 只获取与当前任务直接相关的内容，不无界扩展相邻主题。
3. 不设固定文件数或容量限制；资料缺口已解决且形成可复用入口时停止。
4. 可以创建新资料包、保存原件、制作最小摘要和选择性摘录、更新目录。
5. 每份原件记录官方 URL、文档编号/版本、获取日期、SHA-256 和适用对象。
6. PDF 等大文件必须确认命中 Git LFS。
7. 公开可访问的官方工程资料在许可未明确时可归档，并写
   `redistribution: unknown`。
8. 付费、需登录、保密、泄露或明确限制传播的资料不得归档；只记录允许公开的
   元数据或链接。

下载到临时目录的候选资料只有完成来源、内容、版本和适用范围核验后，才能移入
`library/`。不得用全文 OCR 或全文 Markdown 转换代替按任务组织的摘要和摘录。

## `maintainer`

包含 `autonomous` 的能力，并允许主动进行：

- 元数据完整性和唯一 ID 检查；
- 官方链接有效性及版本更新核验；
- 摘要、摘录、原件和索引的一致性修复；
- 重复资料识别和目录命名规范化；
- 派生目录和质量报告维护。

只有明确的仓库维护任务才应扫描全库。日常业务任务先完成当前目标，并把维护限制
在本次触及的资料包，避免长期启用该模式导致每次任务都消耗大量时间和上下文。

以下动作必须先向用户说明具体目标、影响和恢复方式并取得确认：

- 删除任何原件；
- 用新文件替换而不是并存旧版本；
- 批量移动或重命名资料包；
- 大规模修改目录结构或元数据模式。

禁止重写 Git 历史、强制推送、丢弃用户修改或自动删除仍有兼容性/历史价值的版本。

## 临时权限提升

用户可以用明确指令临时授权超出当前模式的具体动作。例如在 `readonly` 下明确要求
“把这份 PDF 归档并整理”。临时授权遵循：

- 只覆盖用户点名的对象和动作；
- 只对当前任务有效；
- 不修改 `.agent-mode.yaml`；
- 不推导为对相邻资料或全库的额外授权；
- 不自动启用 `auto_commit` 或 `auto_push`，除非用户同时明确要求；
- 仍受运行环境权限和所有共同安全规则限制。

模式配置缺失时不能使用临时授权绕过初始化。

## 自动提交和推送

模式允许写入且配置开启 Git 自动化时：

1. 开始任务时记录当前分支和现有工作区状态。
2. 只暂存本次 Agent 创建或修改的显式路径，禁止使用可能夹带用户修改的宽泛暂存。
3. 无关脏文件保留在原处；路径重叠或无法安全分离时跳过自动提交并报告。
4. 提交前至少检查：
   - Markdown 本地链接；
   - YAML 可解析性和资料包 ID 唯一性；
   - 原件 SHA-256 与元数据一致；
   - 大文件的 Git LFS 属性；
   - `git diff --check`；
   - 摘要、摘录、元数据和目录入口是否同步。
5. 提交信息使用明确范围，例如 `docs(ft6335m): add control extract`。
6. `auto_push: true` 时推送任务开始时所在的当前分支；没有上游时可为该分支设置
   `origin` 上游。

禁止 force push、自动 rebase、修改已有提交、丢弃本地修改或绕过远端保护。
推送失败时停止并报告，不进行破坏性重试。
